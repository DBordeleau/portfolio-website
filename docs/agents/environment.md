# Environment

Things about this machine and repo that cost an agent a wasted turn each time it rediscovers them. Add to this file whenever a session loses a turn to the environment rather than to the problem.

## Shell

On Windows, the shell is PowerShell, with a POSIX `bash` tool also available. They take different syntax and the mistakes are expensive:

- Don't mix them in one command. Pick the shell, then write that shell's syntax throughout.
- In PowerShell, `&&` and `||` don't exist: use `A; if ($?) { B }`. No ternary, no `??`, no `?.`.
- For multi-line strings passed to a native command (commit messages, issue bodies), use a single-quoted here-string with the closing `'@` at column 0, or a `bash` heredoc. Unbalanced quotes in a long `-m` string is the single most common failed call.
- Prefer file-reading and search tools over `Get-Content` / `Select-String` / `cat` pipelines.

## Running the app

`npm run dev` serves the site at http://localhost:3000. Nothing needs to run first, and no env vars are needed to build or browse. The contact form reads `RESEND_API_KEY` and `NEXT_PUBLIC_RECAPTCHA_SITE_KEY`.

If a preview or screenshot step needs a local server, start it the way the project's own launch config does, and expect the first navigation to a new port to need permission. Don't retry a denied navigation; ask once.

## Hooks

`npm install` runs the `prepare` script, `scripts/install-hooks.mjs`, which sets `core.hooksPath` to `.githooks`. To set it by hand: `git config core.hooksPath .githooks`.

## Worktrees

Sessions run in worktrees under a directory the tool chooses. A file outside the session's own worktree may be refused: read and write through the session's own path, and don't reach into another worktree's copy of the repo.

A new worktree has no `node_modules`. Run `npm ci` before any check.

A worktree the Claude desktop app creates can get its own `core.hooksPath` in `config.worktree`, set to the main checkout's absolute `.githooks` path. That overrides the repo setting, and if the main checkout is on an older commit without the hook, pushes skip it silently. Check with `git config --show-origin --get core.hooksPath`, and fix it with `git config --worktree core.hooksPath .githooks`.

Worktrees under `.claude/worktrees/` sit inside the main checkout. ESLint walks up and loads the main checkout's `.eslintrc.json` as well as the worktree's, so `npm run lint` fails there with a `Plugin "@next/next" was conflicted` error. The build prints the same error but still passes.

## Checks

- Typecheck: `npx tsc --noEmit`. It needs `next-env.d.ts`, which is gitignored and generated by `npm run build` or `npm run dev`. On a fresh checkout it fails with TS2307 on the image imports in `lib/data.ts`.
- Unit tests: `npm test`, which runs `node --test` on `scripts/*.test.mjs`. One file: `node --test scripts/branch-name.test.mjs`.
- Full suite: `npm test`, then `npm run build`. The build takes about 30 seconds.
- Lint: `npm run lint`, which runs `next lint`, deprecated in Next 15.5. `npx eslint .` doesn't work until the config moves to an `eslint.config.mjs` flat config.

Run the typechecker and the single relevant test file inside the sub-agent doing the work. Run the full suite once, at the end, in a sub-agent of its own.
